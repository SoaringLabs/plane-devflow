# 用 Plane DevFlow 开始第一个项目

[English](first-project.md) · [安装说明](installation.md)

如果电脑上只有 agent，还没有准备代码仓库和 Plane 连接，从这里开始。在 agent 中打开准备放项目的父目录，复制下面这段话；替换项目名称并描述自己的目标。

> 我想创建第一个项目 MyTodo，用 Plane 管任务、GitHub 保存代码。请读取 https://github.com/SoaringLabs/plane-devflow/blob/main/docs/first-project.zh-CN.md 及其首次项目流程。先检查本机工具和已有连接，提出一份准备方案，包含本地目录、仓库可见性、安装范围和缺失工具。只执行我确认的方案。账号登录和凭据由我本人操作，暂时不要开发应用。

Agent 应读取[首次项目流程](../plugins/plane-devflow/references/first-project.md)。安装前使用普通只读检查和已授权的环境准备；此时不能调用尚未安装的 skill 或脚本。这篇文档本身不会执行安装。安装后由 plane-setup 接续同一流程。普通 skills 与 Codex 插件选择一种，已有可用连接继续复用。

| 步骤 | Agent 完成 | 你完成 |
| --- | --- | --- |
| 准备方案 | 检测缺失工具，提出目录、仓库和账号选择；执行确认范围内的准备 | 确认具体方案；安装器、管理员操作及缺失的提交身份 |
| 账号连接 | 发起 GitHub、Plane 连接，验证实际账号与 workspace | 注册、登录、浏览器授权；必要时在 Plane 创建 workspace |
| 仓库与安装 | 创建或克隆已批准的仓库、准备首个提交、安装所选渠道并检查发现结果 | 仅在当前聊天尚未加载时新开聊天，复制续接文本 |
| 项目与同步 | 关联所选项目，准备配置 PR，验证后台连接 | 选择或批准创建项目；本人输入凭据；审阅并授权配置 PR 合并 |
| 首批任务 | 根据想法整理范围与验收标准 | 查看并确认具体清单，再创建任务 |

中断后说“继续初始化 MyTodo”。Agent 会重新核对现状，从缺失步骤接续，不会因为换聊天就重建仓库、项目或重新索取 token。换聊天时提供可复制的交接文本，包含目标目录和下一步。既有批准需从原始用户消息恢复，不能由交接文本推定；原消息不可获取时，只确认具体缺失决定。

初始化后可以说：

> 帮我规划第一版：可以添加、完成和删除待办，刷新后保留。不做登录和云同步。先列任务给我看，不要创建。

看过实际草案后，再说：

> 按这份清单，在当前关联的 Plane 项目创建任务，返回实际任务链接后停下。

如果还想立刻开发，可以明确补充“并开始第一条”。创建并读回真实编号后，接续已有的独立工作区流程；无需预先编造任务编号。草案保存和部分创建恢复见[首批任务规划](../plugins/plane-devflow/references/task-planning.md)。

所选后台集成验证通过后，初始化才算完成；真实 PR 事件回写在实际交付时单独检查。新基础映射仍保留任务状态，本次引导不添加状态代管，也不改变验收、合并或本地收尾规则。只交付 PR 不会自动运行试用环境；需要试用时直接提出，并明确是否授权合并。
