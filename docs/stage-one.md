# Plane for Codex 第一阶段实现与验证

实施日期：2026 年 10 月 10 日。插件版本：`0.2.0`。这是历史阶段记录；当前公开源码为 `0.4.2`，功能与验证以 [README](../README.md) 和 [0.4.2 验证记录](validation-0.4.2.md) 为准。

本阶段完成基础项目关联与安全重新配置，保留用户已有账号授权。完整产品方案见 [工作流方案](workflow-plan.md)，后续范围见 [改造清单](implementation-plan.md)。

## 0.2.0 阶段可用流程

在目标 GitHub 代码仓库中新开 Codex 聊天，从技能选择菜单选择 **Set Up Plane** 并发送。

首次配置：

1. 复用 Plane/GitHub 已有授权，需要时才进行账号连接。
2. 选择关联已有项目，或创建项目；仓库名称用于推荐和预填，不会自动决定关联。
3. 已有项目按实际 ID 读取；创建项目由 Skill 调用官方 MCP，明确名称和标识后执行。
4. 检查项目及状态列表，无任务的空项目也有效；不要求任务、Cycle 或三个状态，不创建审核状态。
5. 展示关联，保存基础配置，并分别报告本地与真实连接检查结果。

已有配置：

1. 展示已有项目，选择 **检查当前配置** 或 **重新配置**。如果请求已经明确选择，不再重复询问。
2. 检查不会写配置。重配重新选择/创建项目，生成差异计划。
3. 应用时核对规划时的 SHA-256，备份原文件字节并原子替换。取消、并发修改或替换失败保留原配置。
4. 相同关联重跑不改格式、不产生多余备份。账号连接和远端对象不会被删除。

保存配置不自动提交或合并。新任务分支/worktree 仍要求映射已经进入所用基础提交。

## 配置兼容

| 配置 | 本阶段行为 |
| --- | --- |
| version 1 | 保留既有状态 ID、完成策略和人工验收标签；继续使用旧状态同步 |
| version 2 | `states` 为空、`status_sync.enabled=false`；基础关联可用，开发及 PR 报告仍可回写，自动状态保持不变 |

新建关联和切换到不同项目使用 version 2。相同项目优先保留旧配置；用户明确要求关闭旧状态同步时可转换为 version 2。完成偏好保留，但没有状态目标时不会自动写完成状态。

PR 隐藏绑定协议仍为 version 1，不随配置格式升级。旧 PR 与新项目不一致时拒绝写入，不自动迁移旧开发任务。

## 重新配置保护

- 原配置在应用成功前保留；不使用“先删除，再初始化”。
- 备份位于共享 Git 元数据的 `plane-for-codex/backups/`，不随业务代码提交。
- Git 元数据锁协调本插件的并发应用；外部编辑仍通过文件摘要核对识别，不宣称分布式事务。
- 当前关联任务分支不能被重新定向；在基础或专用 setup checkout 中重配。
- 已有事件 workflow（包括本地基础提交里的已知 workflow）阻止替换配置。旧 pinned Action 不理解 version 2，需要先在审阅的 GitHub 变更中处理旧 workflow；本阶段不自动改写它。
- 如果 Plane 项目创建成功而本地配置失败，保留其 ID 供恢复，不自动删除或再次创建。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| 单元与行为测试 | 67 项通过，包含原有 43 项回归和本阶段 24 项测试 |
| 配置与包校验 | 两种配置示例、清单版本和引用校验通过 |
| Skill 校验 | Setup、Start、Deliver 三个入口均通过 |
| 离线开发交付演示 | 通过；使用临时 Git 和模拟 Plane，不写真实服务 |
| 已安装包 | `0.2.0`，13 个源码文件与安装缓存一致 |
| 真实账号连接 | OAuth 工作区、完整项目列表、选定项目及状态读取成功，GitHub 登录可复用 |
| 关联和重配 | 使用真实读取数据在隔离 Git 仓库完成首次关联、相同关联重跑、取消、备份替换与往返恢复 |
| 业务配置保护 | 原业务仓库配置摘要不变；未执行远端创建、状态修改、推送或 PR 操作 |

按用户选择，未创建测试项目，因此真实 `project/create` 写入未验证。项目创建入口和恢复指引已提供；响应校验及空项目保存由测试覆盖，不能替代真实创建权限验证。此阶段也没有逐项点击验证 Codex 的菜单界面。

本地响应快照和验证记录在被忽略的 `.plane-for-codex.local/stage-one/`，不会发布用户的项目 ID 或对象内容。
